# Preserve valid replacement characters in filter input

## Implementation claim

Owner: Codex filter maintenance contributor, delegated by the coordinating
agent during the owner's continued maintenance request. Main at `c87356a`,
the direction plan and live claims were reviewed. No active claim overlaps.

The record-browser filter drops every U+FFFD code point because its sanitizer
compares decoded runes with utf8.RuneError. A valid replacement character is
printable UTF-8; only invalid input bytes should be dropped. An independent
literal case with names Alpha followed by U+FFFD and Beta fails: typing U+FFFD
leaves the filter empty and shows both records instead of one.

Scope: `modeling/tui/templates/state.go.tmpl`,
`modeling/tui/acceptance/filter_test.go.txt`, `modeling/tui/generated_test.go`,
`modeling/tui/examples/browser-filter.cases.json`, `modeling/tui/contract.go`,
`modeling/tui/contract_test.go`, `modeling/tui/hosted_test.go`,
`modeling/tui/options_test.go`, `modeling/tui/README.md`,
`modeling/tui/PROFILE.md`, this task and new immutable Project Memory files.
Keep valid U+FFFD in typed and pasted text while dropping invalid UTF-8 bytes,
controls and line/paragraph separators. Test matching, mixed input, backspace
and the 64-code-point cap in both embed modes; add literal cases. Publish tuic
1.5.1 because generated bytes change, with no model or canonical digest change.
No consumer edits, new filter behavior, profile extensions or owner decisions.

Checks: prove new regressions fail before the fix; full TUI vet and race suite;
Node authoring tests; generator-contract and foundrygen race suites; repository
validation, whitespace checks and committed Project Memory validation. Push and
open a PR for coordinator review; merging belongs to the coordinator.
