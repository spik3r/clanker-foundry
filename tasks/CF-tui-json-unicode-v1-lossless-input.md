# Refuse malformed Unicode escapes in TUI inputs

## Implementation claim

The owner authorized continued Foundry and related UI library improvements with
cheaper delegated agents, independent review and tested PR merges. The coordinator
selected this bounded correctness defect on clean main
`057ff0e7fa6a6dde5f8da2d2e91888dcb5388c5f`, after checking live open PRs,
current priorities and task claims. No Foundry PR was open. Existing filter and
project-file Unicode repairs do not claim these TUI decoder paths.

An independent temporary probe found that TUI model and case decoders accept
lone escaped high and low surrogates. The JSON decoder replaces them with U+FFFD;
a malformed model title and an explicit replacement character then have the
same canonical digest. Refuse the malformed source before that replacement.
This is input correctness maintenance, not a new presentation profile.

The coordinator owns branch `codex/tui-json-unicode` and integration. The delegated
builder may edit only:

- `modeling/tui/model.go` and `modeling/tui/cases.go` to invoke the shared guard;
- new `modeling/tui/json_unicode.go` for a private original-byte Unicode check;
- new `modeling/tui/json_unicode_test.go` for model and case regressions;
- new `modeling/tui/cmd/tuic/unicode_test.go` for existing CLI intake behavior;
- `modeling/tui/README.md` and `modeling/tui/CASES.md` for the refusal contract;
- this task's observed result and new immutable Project Memory source/events.

Check escaped strings in keys and values. Refuse lone high/low surrogates,
reversed or broken pairs, including nested records and expected/filter text.
Keep valid pairs, literal and escaped U+FFFD, ordinary escapes and a literal
backslash followed by `ud800`. Do not reject all decoded replacement characters.
Preserve size/depth/shape checks and existing syntax-error handling. Use fixed
Unicode error text without copying the offending input.

Valid models must retain identical digests and generated bytes. Do not change
profiles, schemas, generator version, templates, manifests, dependencies, runtime,
consumer pins or prior evidence. A version change is unnecessary because valid
generation is unchanged. Keep the helper local to this independent Go module;
do not add a cross-module dependency or general parser abstraction.

## Observed implementation result

The shared private guard checks original JSON string bytes before either TUI
model or case decoding. It refuses unpaired surrogate escapes in keys and
values with fixed error text. Syntax-invalid JSON keeps the existing decoder
error path. No generator version, templates, manifests or dependencies changed.

New regressions failed on unchanged production: malformed model and case text
was accepted, and CLI intake emitted success identities and generated output.
The final tests also failed only the refusal suites against a separate copy of
the pinned unchanged production; valid text and syntax-error tests passed.
After the fix, focused tests passed. Full TUI `go test -race ./... -count=1`,
`go vet ./...` and `go build ./...` passed with Go 1.27.4.

Baseline and fixed CLI binaries produced identical identities and every output
byte for the supplied browser model and seven valid Unicode/escape inputs,
including surrogate pairs, U+FFFD and a literal backslash followed by `ud800`.
CLI regression tests cover validate, generate and check refusals, absent and
existing output paths, empty success output and unchanged existing files.

Repository checks, independent review, Project Memory completion and normal PR
integration remain with the coordinator. This task remains in progress until
those steps and the merge are observed.
