## Finding and intended correction

C06's first action listed its shared working directory and recursively searched
parent directories for instruction filenames before reading its supplied packet.
This violated an explicit supplied-input-only restriction. It revealed unrelated
names, not file contents. The later refusal to invent persistence/authentication
was correct. The original violation is not reclassified as an authorized action.

The generic guidance names write, build and execution scope but does not give
the same concrete treatment to reads, metadata and first-command discovery.
Define exact initial packet/instruction paths, semantic inputs, process/claim
files and permitted repository metadata operations. Treat filenames and directory
enumeration as reads. Anchor actions to named roots rather than the inherited
working directory. Missing files or required instructions call for a named
resolution, not broad ancestor/sibling searches or substitute copies.

Carry the initial boundary in the trusted receiving prompt before any discovery,
not only in the file the worker has not read yet. Preserve higher-priority
instructions: if a required read cannot fit the supplied scope, pause that action
and surface the conflict rather than ignoring instructions or widening access.
Guidance is not an OS sandbox or a guarantee about future agent behavior.
