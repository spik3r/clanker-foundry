## Contract

The skill handles an idea-to-model proposal or first-design handoff, not arbitrary
app generation or permission to implement. Default to clarification/planning when
only an idea is supplied. Saving a draft and running local validation/generation
require the requested scope and a named writable destination. Find an existing
trusted Foundry checkout explicitly; installed skill assets do not imply the
modeling module or toolchain is present. No automatic clone, dependency install,
external transmission or extra skill dependency is required.

Separate stated needs, unresolved questions, assumptions and human decisions.
Ask consequential missing choices rather than silently creating policy. Check fit
against the actual supported profile: unsupported domain data, concurrency, timers,
authentication, persistence, UI and external effects remain outside the model,
not encoded through invented fields or claimed as generated functionality.
AI drafting and model correctness are not deterministic. Only existing fixed
programs' outputs for fixed accepted input/toolchain have reproducibility claims.

Keep original source bytes and semantic identity separate. Validate original
strict model bytes with existing Go APIs/CLI, not only parsed JSON Schema or an
AI judgment. Arrange literal expectations from the requirements independently of
the generated implementation and its results; record provenance limits honestly.
A claimed author label/hash does not prove independence. Never refresh an expected
result or binding to make a tool pass. Preserve substantive mismatches for review.

Generate existing views only as draft review aids in an isolated owned worktree.
A source/table check is not visual inspection; a diagram is not a separate model
or standards-conformance proof. Do not touch or substitute for the denied #20
artifact. Present source model, decision table/diagram identities, requirements,
independent expectation source and pending questions together for human review.
No review/approval is fabricated, and no valid/model-matched status authorizes
execution or integration. Proposed expectations remain unexecuted at this handoff.

The Foundry-specific reference routes to existing tools for subsequent generation,
qualification and explicitly authorized replay. It must distinguish the built-in
runner from separately generated custom-model bindings and state where the current
workflow stops. It must not present an archive export/verify as execution evidence.

The invented worked example contains explicit requirements and example decisions,
a small first model, independently authored literal suite/manifest, a byte-bound
intake declaration and a review handoff with real unresolved authorization/review
gates. These are fictional proposals, not human approvals. A frozen inventory
records exact fixture hashes and independently checked semantic identities before
integration-test logic. The Go test uses existing APIs only to check profile,
strict model/intake binding, model/suite declaration consistency and generated
review artifacts/code syntax. A panic sentinel prevents executing the example;
no new production runner, parser, compiler or utility is added.

Negative integration controls preserve rather than repair unanswered questions,
source drift, invalid models and stale suite binding. They must fail for the
intended observed reason. The test does not claim to automate human reasoning or
visual approval. Independent skill forward-tests are separate behavioral evidence,
not regex checks for favored wording. Existing installation and repository
conventions remain intact.
